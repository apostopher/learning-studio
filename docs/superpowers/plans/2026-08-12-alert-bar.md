# Optional Alert Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an optional 12px bar pinned to the top of every screen behind login, its background colour driven by an optional env var, with a `children` slot that renders the bar even when empty.

**Architecture:** A new optional client env var (`VITE_ALERT_BAR_COLOR`) flows through the existing build-time theme generator, which emits a `--color-alert-bar` CSS custom property and a `alertBarColor: string | null` TS export. `src/styles.css` owns the `.alert-bar` rule (absolute, top of viewport). A hookless presentational `AlertBar` component renders the strip; `src/routes/_authed.tsx` mounts it only when `alertBarColor !== null`.

**Tech Stack:** TanStack Start + React 19, Tailwind v4 (`@theme` blocks), `@t3-oss/env-core` + Zod for env validation, Vitest + `@testing-library/react` (jsdom), Biome for format/lint.

## Global Constraints

- **Read the spec first:** `docs/superpowers/specs/2026-08-12-alert-bar-design.md`. It carries the rationale for every decision below.
- **Logical CSS properties only.** `inset-block-start`, `inset-inline`, `min-block-size` — never `top`/`left`/`right`/`min-height`. This is a hard project rule.
- **Presentational components must be hookless.** No `useState`, `useEffect`, `useRef`, or any hook in `AlertBar`. react-compiler plus Vitest nulls the React dispatcher, so a hook makes the render test crash.
- **No `jest-dom`.** It is not installed. Assert with `toBeDefined()`, `getAttribute()`, `textContent`, `container.querySelector()` — never `toBeInTheDocument()` or `toHaveAttribute()`.
- **Test imports:** Vitest cannot resolve the `@/` alias in this repo. Use relative paths (`../alert-bar`) or the `#/` subpath import.
- **`src/styles.css` is excluded from Biome** (see `biome.json` `files.includes`: `"!**/src/styles.css"`). Do not attempt to format it; match the surrounding hand-written style.
- **Quote style: single quotes everywhere**, per Biome's `javascript.formatter.quoteStyle: "single"`. Note `src/routes/_authed.tsx` currently uses double quotes and **already fails `pnpm biome check` at baseline** for that reason. It is a 13-line file, so let Biome reformat it wholesale (`biome check --write`) rather than adding non-conforming lines to it. This was an explicit pre-flight decision — the ~4 converted pre-existing lines are expected diff, not scope creep.
- **The generated theme files are gitignored.** `src/styles/theme.generated.css` and `src/styles/theme.generated.ts` are produced by `plugins/vite-theme.ts` on `buildStart` and on `.env.local` change. Never edit or commit them. Never write a test that reads them.
- **Colour value:** `#cb0d39`, which is exactly `rgb(203, 13, 57)`.
- **Run tests with:** `pnpm vitest run <path> -t "<test name>"`. The `test` package script is `vitest run`.
- **Typecheck with:** `npx tsc --noEmit`.

import { readFileSync } from 'node:fs'
import { resolve } from 'node:path'

/**
 * A generated token that nothing reads is dead code, and this codebase's most
 * common defect shape. Pin both ends of the seam: the generator must emit the
 * property, and styles.css must consume it under exactly that name. Renaming
 * either side fails this test.

describe('alert bar token consumer seam', () => {
  const stylesCss = readFileSync(
    resolve(process.cwd(), 'src/styles.css'),
    'utf8',
  )

  it('styles.css consumes the property the generator emits', () => {
    const css = buildThemeCss({
      gray: { light: '#8B8D98', dark: '#8B8D98' },
      bg: { light: '#ffffff', dark: '#111111' },
      panelBg: { light: '#ffffff', dark: '#111111' },
      shellBg: { light: '#ffffff', dark: '#111111' },
      fontFamilies: {
        sans: 'Inter',
        mono: 'IBM Plex Mono',
        display: 'Inter',
        serif: 'Newsreader',
      },
      brandColors: [{ name: 'solo', light: '#3D63DD', dark: '#3D63DD' }],
      alertBar: '#cb0d39',
    })

    expect(css).toContain('--color-alert-bar:')
    expect(stylesCss).toContain('var(--color-alert-bar)')
  })

  it('.alert-bar positions itself with logical properties only', () => {
    const rule = stylesCss.slice(
      stylesCss.indexOf('.alert-bar {'),
      stylesCss.indexOf('}', stylesCss.indexOf('.alert-bar {')),
    )

    expect(rule).toContain('position: absolute')
    expect(rule).toContain('inset-block-start: 0')
    expect(rule).toContain('inset-inline: 0')
    expect(rule).toContain('min-block-size: var(--alert-bar-min-block-size)')

    expect(rule).not.toMatch(/\b(top|left|right|bottom|min-height):/)

- [ ] **Step 1: Write the failing component test**

Create `src/components/__tests__/alert-bar.test.tsx`. The `// @vitest-environment jsdom` pragma on line 1 is required — the project has no global jsdom default:

```tsx
// @vitest-environment jsdom
import { render, screen } from '@testing-library/react'
import { describe, expect, it } from 'vitest'
import { AlertBar } from '../alert-bar'

describe('AlertBar', () => {
  it('renders the strip even with no child', () => {
    const { container } = render(<AlertBar />)
    expect(container.querySelector('.alert-bar')).not.toBeNull()
  })

  it('hides the empty strip from assistive tech', () => {
    // Empty, it is decorative chrome carrying no information. Announcing an
    // unlabelled element on every authed screen is noise.
    const { container } = render(<AlertBar />)
    const bar = container.querySelector('.alert-bar')
    expect(bar?.getAttribute('aria-hidden')).toBe('true')
  })

  it('treats an explicitly null child the same as no child', () => {
    const { container } = render(<AlertBar>{null}</AlertBar>)
    const bar = container.querySelector('.alert-bar')
    expect(bar).not.toBeNull()
    expect(bar?.getAttribute('aria-hidden')).toBe('true')
  })

  it('renders a child and stops hiding itself, so the child owns its own role', () => {
    const { container } = render(
      <AlertBar>
        <p role="alert">SCHEDULED_MAINTENANCE</p>
      </AlertBar>,
    )
    const bar = container.querySelector('.alert-bar')
    expect(bar?.getAttribute('aria-hidden')).toBeNull()
    // The consumer's own role must actually reach the accessibility tree —
    // an aria-hidden ancestor would remove it.
    expect(screen.getByRole('alert').textContent).toBe('SCHEDULED_MAINTENANCE')
  })
})
```

- [ ] **Step 3: Write the component**

Create `src/components/alert-bar.tsx`. Hookless — see Global Constraints:

```tsx
import type { ReactNode } from 'react'

type AlertBarProps = {
  /**
   * Optional alert to display. The bar renders as a bare strip when this is
   * absent, so the surface is always present and a future alert component can
   * drop straight in.
   */
  children?: ReactNode
}

/**
 * Bar pinned to the top of every screen behind login. Mounted by
 * `src/routes/_authed.tsx` only when `VITE_ALERT_BAR_COLOR` is set; its
 * background and resting height come from `.alert-bar` in `src/styles.css`.
 *
 * `aria-hidden` while empty: the strip is decorative chrome on its own, and an
 * unlabelled announced element on every page is noise. Dropped as soon as a
 * child arrives, so the child's own role reaches the accessibility tree.
 */
export const AlertBar = ({ children }: AlertBarProps) => (
  <div className="alert-bar" aria-hidden={children == null ? true : undefined}>
    {children}
  </div>
)
```

`children == null` is a deliberate loose equality: it catches both `undefined` (no child) and `null` (explicit null child).
