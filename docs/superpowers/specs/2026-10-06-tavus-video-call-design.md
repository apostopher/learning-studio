# Tavus video call in the Viper chat — design

Date: 2026-10-06

## Problem

Viper7 is text (and push-to-talk) only. We want a face-to-face option: a
video-call button in the Viper chat window that puts the learner on a live
call with a Tavus replica speaking **as Viper7** — same persona, same course
knowledge, same lesson gating as the text chat.

## Decisions

- **Our server is the brain.** Tavus supplies face, voice, speech
  recognition and turn-taking; every reply is generated by our own
  `buildChatStream` via Tavus's *custom LLM* layer. Persona, RAG, gating and
  SKA profile are identical to `/api/chat`.
- **One Tavus persona per environment + DB lookup.** Identity comes from the
  `conversation-id` header Tavus sends on every completions request (verified
  by spike, below), resolved against our own `video_calls` row.
- **Access:** every signed-in user, Viper7 mode only (never onboarding).
- **Limits:** 10 min per call, 30 min per user per day (day boundary: 00:00
  UTC), one active call per user.
- **Placement:** call runs inside the chat window; can pop out into its own
  draggable, resizable floating window and dock back.
- **Transcript:** appended to the current Viper chat after the call, marked
  as from the video call.
- **Perception stays on at Tavus, but is dropped by us.** The
  `<user_appearance>` / `<user_emotions>` system messages are stripped at
  the top of our completions endpoint and never reach the model, logs or DB.
- **Custom call UI on `@daily-co/daily-js`** (call object, no iframe, no
  Daily Prebuilt chrome).

## Spike findings (2026-10-06, throwaway, cleaned up)

A logging stub behind ngrok was set as a test persona's custom LLM; one live
call was made.

1. Every request carries the real conversation id in a `conversation-id`
   header (also `conversation_id`). During persona-config validation Tavus
   sends a connectivity check with the placeholder id
   `tavus-openai-compat-test`.
2. The configured `layers.llm.api_key` arrives as `Authorization: Bearer …`;
   custom `layers.llm.headers` are passed through.
3. Requests are stateless OpenAI chat-completions, `stream: true`, full
   history each turn. Client is `OpenAI/Python` with a **10 s read timeout**.
4. Tavus prepends ~4k chars of system content: the persona `system_prompt`,
   then its own TTS rules, a **mandatory `<emotion value="…"/>` SSML tag at
   the start of every reply**, perception instructions, a date/time message,
   and finally `conversational_context` appended to the end of the first
   system message. Perception arrives as separate `system` messages
   containing `<user_appearance>` / `<user_emotions>` (which include guessed
   ethnicity and skin tone).
5. A reply can be interrupted mid-stream, so what we generate is not always
   what was spoken.
6. `conversation_url` is a Daily room (`https://tavus.daily.co/<id>`).

## Configuration

`src/env.ts` (server, required):

| Var | Meaning |
| --- | --- |
| `TAVUS_API_KEY` | Tavus API key |
| `TAVUS_REPLICA_ID` | replica (face), currently `r93ce3db27f8` |
| `TAVUS_PERSONA_ID` | per-environment persona whose LLM layer points at us — **optional**: unset → the button is locked with "Video calls aren't set up on this server yet." (lets the dev server boot before `sync-persona` has run) |
| `TAVUS_LLM_SECRET` | random secret (≥ 32 chars); the persona's `layers.llm.api_key`; the webhook token is derived from it as `HMAC-SHA256(TAVUS_LLM_SECRET, 'tavus-webhook')` hex, so the raw secret never appears in a URL |
| `TAVUS_PUBLIC_URL` | public origin Tavus can reach (`https://…ngrok.app` in dev, the deployed origin in prod) — used for the persona's `base_url` and the webhook `callback_url` |

**`pnpm tavus:sync-persona`** creates or updates the environment's persona:
replica, `pipeline_mode: "full"`, `layers.llm` = `{ model: "viper7",
base_url: <APP_URL>/api/tavus/v1, api_key: TAVUS_LLM_SECRET }`, perception
left on. Prints the persona id to put in env. Dev points `APP_URL` at an
ngrok URL; prod at the deployed origin. The existing dashboard persona
"Viper 7" (`pc0f4171a549`) is not modified; its prompt is superseded by the
org persona.

## Data

New table `video_calls`:

| Column | Notes |
| --- | --- |
| `id` | uuid pk |
| `user_id` | fk users |
| `chat_id` | fk chats — the Viper chat the call belongs to (created if absent) |
| `course_slug` | nullable — course in context when the call started |
| `user_name` | nullable — session name at start; the completions endpoint has no session |
| `tavus_conversation_id` | unique |
| `status` | `'active' \| 'ended'` |
| `reserved_seconds` | `max_call_duration` sent to Tavus |
| `started_at`, `ended_at` | |
| `duration_seconds` | actual, set on end; null while active |
| `end_reason` | `'user' \| 'time_limit' \| 'left' \| 'error' \| 'stale'` |
| `transcript_saved_at` | idempotency guard for transcript append |

Unique partial index on `user_id` where `status = 'active'`. No `org_id`:
the org is deployment configuration (`getActiveOrgId()`), exactly as in
`/api/chat`.

**Daily usage** = Σ over today's (UTC) rows of `max(60, duration_seconds)`
for ended calls + `reserved_seconds` for active ones. Remaining = 1800 −
usage. The 60 s minimum charge per ended call matches Tavus's per-minute
billing, so many very short calls can't each cost a billed minute while
barely touching the daily limit.

Schema change goes in via a hand-written idempotent script
(`pnpm db:migrate-video-calls`), never `db:push` — push offers to truncate
`docs` over unrelated drift.

## Server

### `POST /api/video-call` (session required)

1. Mark the user's stale active rows (`started_at + reserved_seconds + 120 s
   < now`) as ended, `end_reason: 'stale'`, `duration_seconds =
   reserved_seconds`.
2. Compute remaining seconds today. If < 60 → `403 { reason:
   'daily_limit', resetsAt }`.
3. Ensure the chat row: `ensureChat({ chatId, userId, firstUserText:
   'Video call with Viper7' })` — continues the owned chat if `chatId` is
   passed, otherwise creates one titled from that text. The returned id goes
   back to the client so the widget switches to that chat.
4. `reserved = min(600, remaining)`. Create the Tavus conversation:
   `persona_id`, `replica_id`, `callback_url = <TAVUS_PUBLIC_URL without trailing slash>/api/tavus/webhook?token=<HMAC-SHA256(TAVUS_LLM_SECRET, 'tavus-webhook') hex>`,
   `properties: { max_call_duration: reserved, participant_left_timeout: 30,
   participant_absent_timeout: 120 }`.
5. Insert the `video_calls` row. Unique-index violation → end the just-made
   Tavus conversation, return `409 { reason: 'already_active' }`.
6. Tavus failure → no row, `502 { reason: 'provider_unavailable' }`.

Order: allowance and active-call checks → create Tavus conversation (with a
fixed `custom_greeting`, so the greeting costs no LLM call) → `ensureChat` →
insert. Returns `{ id, conversationUrl, endsAt, chatId }`.

### `GET /api/video-call/:id` (session, owner only)

`{ status, endReason, durationSeconds, transcriptSaved, chatId }`. While the
transcript is unsaved it calls `reconcileVideoCall` first, so client polling
after hang-up is what normally brings the transcript in (Tavus's
transcription event lands seconds after shutdown).

### `GET /api/video-call/allowance` (session required)

`{ remainingSeconds, resetsAt, activeCallId | null }` — drives the button's
locked state.

### `POST /api/video-call/:id/end` (session, owner only)

Ends on Tavus (ignore "already ended"), then `reconcileVideoCall(id)`.

### `POST /api/tavus/v1/chat/completions`

1. Bearer must equal `TAVUS_LLM_SECRET` (timing-safe) → else 401.
2. `conversation-id === 'tavus-openai-compat-test'` → stream a fixed
   confirmation (Tavus's config check).
3. Look up an **active** `video_calls` row by conversation id → else 401.
4. Clean messages: drop messages of any role containing a
   `<user_appearance`, `<user_emotions` or `<user_screen` tag (with or
   without attributes). `sync-persona` sets the Tavus persona's
   `system_prompt` to the sentinel line `[[VIPER7_PERSONA_PROMPT]]`, which
   Tavus places at the start of the first system message; remove that line,
   keeping the rest (Tavus's TTS/emotion rules) and the date/time message.
   We send no `conversational_context`. The remaining Tavus system text is
   passed to `buildChatStream` as an extra system block after our own
   prompt.
5. Call `buildChatStream` with the row's user, course, org persona
   (`resolvePersonaForChat`), SKA profile, and **the chat's persisted
   messages (`getChat`) followed by the cleaned call history**, so Viper on
   video knows what was said in text before the call. Only `user`/`assistant`
   rows are replayed (a stored `system` row never becomes a system prompt),
   capped to the last 30. `buildChatStream`
   gains a `voice` option: appends a voice-mode prompt (spoken style, short
   answers, no markdown) plus Tavus's rules to the system prompt, and
   switches `smoothStream` from `'line'` to `'word'` chunking (line chunking
   would hold a newline-free spoken reply back until it finished). It also
   gains `abortSignal`. For every caller (text chat and call turns),
   `buildChatStream` converts `data-notification` parts to a bracketed text
   part (`[Video call with Viper7]`), ignores incomplete tool calls, and drops
   any model message left with no content — a data-only assistant turn would
   otherwise reach Gemini as an empty `model` turn and 400.
6. Pipe through `toOpenAIChatCompletionStream` (new adapter): AI SDK text
   deltas → `chat.completion.chunk` SSE, final `finish_reason: "stop"`,
   `data: [DONE]`. Request `AbortSignal` is passed through so an interrupted
   turn stops generation.
   Until the first token, an SSE comment (`: keepalive`) is written every
   2 s so a slow `searchKB` step can't trip Tavus's 10 s read timeout.
7. If generation throws before the first token (or finishes with no text), stream a spoken fallback
   (`<emotion value="neutral"/>Sorry, I lost that. Could you say it again?`)
   and log the error. Nothing is persisted from this endpoint.

### `POST /api/tavus/webhook?token=…`

Token must equal `HMAC-SHA256(TAVUS_LLM_SECRET, 'tavus-webhook')` hex (timing-safe). Body is used only to read the
conversation id; on `system.shutdown` or `application.transcription_ready`
it calls `reconcileVideoCall` for the matching row. Always 200 for unknown
ids.

### `reconcileVideoCall(id)` (server-only module)

1. `GET /v2/conversations/:cid?verbose=true` with our key.
2. If ended and our row is active: set `ended_at` (shutdown event time),
   `duration_seconds` (clamped to `reserved_seconds`), `end_reason` (from
   `shutdown_reason`: `max_call_duration` → `time_limit`,
   `participant_left_timeout` → `left`, explicit end → `user`).
3. If a transcript is present and `transcript_saved_at` is null: keep only
   `user`/`assistant` turns, drop the `custom_greeting`-only assistant turn
   if empty, strip `<emotion …/>` and other SSML tags, and append them to
   `chat_id`, bracketed by two `data-notification` messages ("Video call
   with Viper7" / "Video call ended · 8 min") — the widget already renders
   that part type as a muted status line, and `ai_messages` has no metadata
   column. Claiming `transcript_saved_at` and inserting happen in one
   transaction.
4. Safe to call repeatedly.

## UI

Containers own state and data; presentational components are props-only.

**Atoms** (`src/atoms/video-call.ts`): `videoCallAtom` (`idle | requesting-media
| connecting | live | reconnecting | ending | ended | error`, call id,
`endsAt`, error reason), `videoDockedAtom` (boolean), `videoWindowRectAtom`
(persisted, same shape as `chatWidgetRectAtom`).

**Data hooks:** `useVideoCallAllowance`, `useStartVideoCall`,
`useEndVideoCall` (TanStack Query; end invalidates the allowance and the
chat's messages).

**Geometry:** `useChatWindowGeometry(rectAtom)` takes its rect atom as a
parameter; the chat window passes `chatWidgetRectAtom`, the video window
`videoWindowRectAtom`.

**Entry point:** a `Video` icon `HeaderControlButton` in
`ChatWidgetHeader`, Viper7 mode only.
- Locked: disabled; tooltip and accessible name both state the reason and
  the unlock — "Video call unavailable. You've used today's 30 minutes.
  Resets at 00:00 UTC." / "…A previous call is still closing. Try again in
  a minute." (typically a reload mid-call; while that reason shows, and this
  tab has no call, the allowance is re-checked every 10 s).
- Click → request microphone (camera off by default) → "Connecting to
  Viper…" → live. Mic denied → inline explanation of how to allow it; no
  call is created.

**In-call (docked):** Viper's video fills the message area (`object-fit:
contain` on the gray-2 surface); optional self-view thumbnail. Control bar:
mute, camera, time left (`tabular-nums`, `mm:ss`), pop out, **End call**
(red-9 with `text-black` — white fails AA on red-9). At 60 s left an
`aria-live="polite"` banner: "1 minute left".

**Popped out:** separate floating window (same chrome, own geometry); its
close control is labelled "End call". The chat window returns to messages
with a slim bar "On a call · mm:ss · Bring video back". Closing the chat
window while popped out leaves the call running; while docked, closing the
chat window ends the call. Below 640 px viewport width there is no pop out.

**After:** "Saving the call transcript…" in the chat window while the
client polls `GET /api/video-call/:id` (every 3 s, up to 20 times). The
Viper7 widget has no server rehydration (its `useChat` state is the only
copy), so once `transcriptSaved` is true the container loads
`/api/chats/:chatId` and replaces the widget's messages with the persisted
history (`setMessages`) — the transcript and its bracketing status lines
appear, and later text turns carry the call as context. The widget also
adopts the call's `chatId`. If polling gives up: "The transcript will
appear in this chat shortly." 

**Motion:** open/close/pop-out on Motion springs; reduced motion → opacity
only. Network reconnecting → "Reconnecting…" overlay.

## Error handling summary

| Case | Behaviour |
| --- | --- |
| Tavus create fails | no row; "Couldn't start the video call. Try again in a moment." |
| Concurrent start | 409, locked reason "A previous call is still closing. Try again in a minute." |
| Tab closed mid-call | Tavus ends after 30 s; webhook reconciles; stale sweep is the backstop |
| Completions error | spoken fallback, logged |
| Request for ended/unknown call | 401 |
| Webhook missing | end route reconciles; reconcile is idempotent |

## Testing

Assert on what the consumer received (repo testing rule):

- **Completions endpoint:** stubbed `buildChatStream` is *called with* the
  row's user/course/persona and cleaned messages (no perception messages, no
  Tavus persona prompt, TTS rules kept). 401 for bad secret, unknown id,
  ended call; config-check id streams the confirmation.
- **`toOpenAIChatCompletionStream`:** chunk shape, `finish_reason`,
  `[DONE]`, fallback on early error, abort propagation.
- **Start route:** stubbed Tavus client *called with* `max_call_duration =
  min(600, remaining)`; daily limit 403 with `resetsAt`; 409 on unique
  violation ends the orphaned conversation; stale sweep.
- **Reconcile:** `appendMessages` *called with* cleaned, tagged turns;
  second call is a no-op; duration clamped; end-reason mapping.
- **UI (hookless presentational):** locked button label/accessible name,
  timer formatting, one-minute banner.
- **Manual (browser via ngrok):** full call; pop out, drag, resize, dock;
  daily limit lock; transcript appears in chat.

## Out of scope

Subscription gating (no subscriptions reader yet), onboarding-mode video,
screen share, per-user time zones for the daily reset, admin usage
dashboards.
