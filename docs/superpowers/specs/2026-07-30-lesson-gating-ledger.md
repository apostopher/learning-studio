# Shared understanding: lesson gating (video-watch + dependencies)

Date: 2026-07-30 · Branch: `feat/lesson-config-and-course-import`

## Goal

Port the old platform's content gating (`airmanship-web`) into rmtp-studio: a
lesson's video and material stay locked until the student has satisfied its
prerequisites and watched its video. Three gates — video-watch, lesson
dependencies, module dependencies — plus the session and subscription
authorization the route is missing entirely today.

Governing UX principle, stated by the user and applied throughout: **no locked
state without a stated reason. Never make the student guess.**

## Decisions

| #   | Decision                                                                                           | Chosen                                                                                                                                               | Rationale                                                                                                                                                     |
| --- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Which gates ship                                                                                    | All three: video-watch, lesson `dependsOn`, module `dependsOn`                                                                                        | All three have authored data in the DB; enforcing a subset leaves authored intent unenforced and produces incoherent half-states                                |
| 2   | `needsVideoWatch: true` on a lesson with no video                                                   | Gate **passes**. Predicate guards on `videoId`, not a data cleanup                                                                                   | 20 lessons are in this state today and the column defaults to `true`, so it recurs on every video-less lesson an admin creates                                  |
| 3   | Synthetic dependency injection (`src/db/course.ts:158-170`, `mod.id > 1 && mod.id < 6`)              | **Delete it.** Enforce against `lesson_dependencies` rows only                                                                                        | Hard-coded module ids written for 3d-airmanship now resolve to three ITPS modules; enforcing would silently make 36 lessons sequential. User: "demo purpose"    |
| 4   | Definition of "satisfied" for a lesson                                                              | One predicate: `!needsVideoWatch \|\| !videoId \|\| hasWatchedVideo(user, videoId)`. Used for the lesson itself, its prereqs, and module prereqs      | Applies the no-video escape transitively for free; writing it twice guarantees divergence, and the cost of divergence is a permanently dead chain tail          |
| 5   | "Watched" threshold                                                                                 | This repo's lenient definition — every milestone **except** 100 (`isVideoWatched`)                                                                    | Old repo required `progress === 100`; this repo deliberately tolerates stopping a few seconds early. Divergence accepted knowingly                              |
| 6   | Locked response shape                                                                               | `200` + discriminated union, content nested under `material` so it is structurally absent when locked                                                 | Flat-null shape leaks any newly added column until someone remembers to null it; `403` would be swallowed by the wrapper's existing `isError → null`            |
| 7   | `text` in the unlocked response                                                                     | **Keep it.** Old repo omitted it                                                                                                                     | `lesson-player-container.tsx:45` feeds `material.text` into debrief-quiz generation; a literal port breaks the debrief silently                                 |
| 8   | Authorization on `/api/lesson/material`                                                             | `401` anonymous, `403` signed-in but not subscribed, then the gates                                                                                  | The route has **no auth at all** today. Without the subscription check, a free signup bypasses the gate entirely and only honest users are inconvenienced       |
| 9   | Anti-skip enforcement                                                                                | Fix `useMilestoneReporter` to report only milestones **crossed by playback** (interval `(prevPercent, currentPercent]`), nothing on a seek            | Today it reports every milestone `<= percent` from an empty set, so `End` or one scrubber drag reports all 19 and unlocks instantly                             |
| 10  | Milestone ordering                                                                                  | **Not enforced.** Coverage is the only requirement; any order, across any number of sessions                                                          | User: watching the last 3 minutes then the first 3 is legitimate. `hasWatchedVideo`'s `countDistinct` already models coverage correctly                         |
| 11  | Detecting completion without a page refresh                                                         | Seed `reportedRef` from `GET /api/user/video-progress` on mount; on local coverage, re-fetch and re-report any diff, then invalidate the material key | One extra GET per lesson load instead of ~40 polls per 20-min lesson, and it is exact rather than up to one interval late. Handles cross-session coverage       |
| 12  | Cache policy                                                                                        | `locked: true` responses get `staleTime: 0`; unlocked keeps the existing 1 hour                                                                       | A stale *locked* response is harmful; a stale *unlocked* one cannot be. Covers second tabs and refocus                                                          |
| 13  | AI chat access to locked material                                                                   | `getCourseContentForAgent` filtered to the user's unlocked lessons, same predicate                                                                    | `search-kb` currently feeds every lesson's `text` and `proTips` to the model with no user filter — the chat is one tap from the lock and would defeat it        |
| 14  | `courseSlug` threading into `search-kb`                                                             | Thread it through from `chat.ts`                                                                                                                     | `chat.ts:70` omits it and `search-kb.ts:32` defaults to `'3d-airmanship'`, so every chat answer is built from the wrong course. Pre-existing bug, fixed en route |
| 15  | Admin access                                                                                        | Admins bypass subscription **and** all three gates, in the endpoint and in the chat. Response carries a bypass flag                                    | Admins author the content; and a silent bypass makes the feature untestable — an admin can't distinguish a working gate from a broken one                       |
| 16  | Scope of the dependency gates                                                                       | Lock the **whole lesson** — video and material                                                                                                       | Material-only sequencing isn't sequencing: the student gets the teaching and loses only the quiz. Also avoids a dead debrief button after a full watch          |
| 17  | Video-gate scope                                                                                    | Material only                                                                                                                                        | The video is how the gate is satisfied                                                                                                                         |
| 18  | Video ends but coverage incomplete                                                                  | Replace `DebriefOverlay` with a coverage state: "You've watched N of 19 sections. Watch the parts you skipped to unlock the material."                | The one case where the student's mental model is confidently wrong. Silence here turns a working gate into a support ticket                                     |
| 19  | Sidebar lock state                                                                                  | Show lock + reason per lesson, computed **client-side** from data already fetched (`dependsOn` + `progress-summary`'s per-lesson `watched`)           | No new endpoint, no new requests. Clicking into a lesson to discover it's locked is exactly the guessing the principle rules out                                |
| 20  | Where per-user lock state must **not** go                                                           | Never into `getCourseDetails` / `getCourseDetailsWithCache`                                                                                          | That's a Redis cache keyed by course slug only — per-user data there is served to every other student                                                          |
| 21  | Predicate duplication (server + client)                                                             | One pure function in `src/lib/`, unit-tested, imported by both                                                                                       | Server enforces, client displays; a second implementation would drift                                                                                          |
| 22  | `is_available = false` lessons                                                                      | Excluded from **all** gate logic — as prerequisites and as targets                                                                                    | User: WIP lessons, not ready for students. 5 edges point at unavailable lessons today; `swiss-cheese` would otherwise be permanently dead mid-chain             |
| 27  | `getCourseDetails`'s discarded `isAvailable` filter and rank sort (`course.ts:156-158`)             | **Apply both** — assign the filtered, sorted array back to `mod.lessons`                                                                              | The filter and sort are computed into a new array that is never assigned, so all 23 WIP lessons are served to students today and modules come back in join order rather than rank order. Deleting the synthetic block (#3) removes their only consumer |
| 28  | Where the WIP filter applies                                                                        | **Learner path only.** The admin editor keeps listing every lesson, available or not                                                                  | `is_available` is set in the editor, alongside dependencies — an editor that hid WIP lessons could never make one available again. Safe by construction: `getCourseDetails` has exactly one caller (`/api/course/details`), while the editor reads `getCourseBoard` (`src/db/admin.ts:255-275`), which has no availability filter |
| 23  | Prerequisites that are missing or deleted                                                           | Do not block. Logged server-side                                                                                                                     | Same structural class as #2 and #22 — the dependency graph is edited independently of availability and video assignment, so unsatisfiable edges keep appearing  |
| 24  | Kill switch                                                                                         | **None.** Gates always on                                                                                                                            | User's call. Admin bypass is the escape hatch                                                                                                                  |
| 25  | Module gate semantics                                                                               | Same predicate, over every available lesson of each prerequisite module                                                                               | User: "same as lessons"                                                                                                                                        |
| 26  | Dependency traversal depth                                                                          | Direct edges only                                                                                                                                    | Transitivity emerges: a locked lesson is unplayable (#16), so its video can't be watched, so its dependents stay locked                                         |

## Failure behaviour

| Scenario                                                    | What happens                                                                  | User sees                                                                       |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Not signed in                                                | `401`                                                                         | Redirect to login (existing `_authed` behaviour)                                 |
| Signed in, not subscribed to the course                      | `403`                                                                         | Not-subscribed state                                                             |
| Lesson prerequisite unsatisfied                              | Whole lesson locked; video not served                                          | "Finish **{lesson name}** first", with a link to that lesson                      |
| Module prerequisite unsatisfied                              | Whole lesson locked                                                            | "Finish **{module name}** first"                                                  |
| `needsVideoWatch`, video present, coverage incomplete        | Video plays; material `locked: 'video'`                                        | Locked panel: "Watch the video to unlock this material"                           |
| Video ends, coverage incomplete (student skipped)            | Debrief overlay suppressed; coverage state shown instead                       | "You've watched N of 19 sections. Watch the parts you skipped to unlock."         |
| `needsVideoWatch`, no video on the lesson                    | Gate passes                                                                    | Normal unlocked material                                                          |
| Prerequisite is `is_available = false`                       | Edge ignored                                                                   | Normal unlocked material                                                          |
| Prerequisite slug missing / deleted                          | Edge ignored, logged                                                           | Normal unlocked material                                                          |
| Milestone beacon dropped in flight                           | Reconcile on local coverage re-fetches and re-reports the diff                 | Nothing — unlock proceeds                                                         |
| Gate query throws (DB error)                                 | `500` — **not** a lock                                                         | Error state with retry, never a false lock (assumed, see below)                   |
| Material row missing for an unlocked lesson                  | `404`                                                                          | Existing not-found handling                                                       |
| Material row missing for a **locked** lesson                 | Locked response, gate evaluated first                                          | Locked panel — existence not revealed                                             |
| Student opens a second tab                                   | Server union is authoritative; locked responses aren't cached                  | Both tabs converge on refocus                                                     |
| Admin views any lesson                                       | All gates and subscription bypassed                                            | Content, plus "Admin preview — gates bypassed"                                    |

## Accepted risks

- **The gate is honest-student-grade, not secure.** `/api/user/report-video-progress` accepts any `videoId`/`progress` from any signed-in user, so 19 scripted POSTs unlock anything. No cheap server-side check survives the out-of-order requirement (#10). Realistic threat is idle scrubbing, not scripting.
- **Lenient watched threshold** — stopping at ~96% unlocks. Deliberate (#5), diverges from the old platform.
- **Client/server predicate duplication** can drift despite the shared pure function, if a caller reimplements it.
- **3d-airmanship is effectively ungated**: its 4 lessons have no videos and no dependency rows, so all three gates pass. Not a defect — a consequence of its data.
- **Gating is enforced per-request, not per-session**; a student who loses subscription mid-video keeps the already-delivered material until refetch.

## Assumed (not confirmed)

Defaults I filled in without asking — say if any is wrong:

- Gate errors return `500` with a retryable error UI rather than failing closed into a false lock (the only option consistent with the "state the reason" principle).
- Gates are evaluated **before** the material-existence check, so a locked lesson never reveals whether material exists.
- Locked material renders as **one panel replacing the tab strip**, not seven individually-locked tabs — both old-repo branches locked all sections anyway.
- A prerequisite-locked lesson page replaces the player with a locked card naming the blocking lesson/module and linking to it.
- The lock reason lives in the accessible name, not hover-only, and the sidebar lock is not colour-only.
- Admin bypass renders as a small inline note above the tabs, nothing elaborate.
- Tests follow this repo's CLAUDE.md rule — assert on what the **consumer** received (the gate's effect on the response and on the chat context), and each regression test is verified red against the unfixed code first.

## Out of scope

Parked, with what would bring each back:

- **Per-lesson chat personalization** (user: "we can customize that later") — brought back when the chat should scope answers to the current lesson.
- **"View as student" toggle** for admins — brought back if QA-ing gates against the admin bypass becomes painful.
- **Missed-range visualisation on the scrubber** — the milestone set already gives ranges, so this is cheap whenever the coverage message proves insufficient.
- **Server-side watch-window validation** (elapsed time vs video duration) — needs duration in the DB; brought back if scripted unlocking is observed.
- **`/api/lesson/ai-test/generate` as an open LLM proxy** — any signed-in user can post arbitrary text. Cost-abuse issue, unrelated to gating.
- **Admin-facing warning for unsatisfiable dependency edges** — the server log (#23) is its input; brought back if edges keep breaking silently.
- **Course-tree gating beyond the sidebar** (e.g. the course index page) — unless it already lists lessons.
